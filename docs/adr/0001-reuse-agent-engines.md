# ADR-0001 复用现成的 Agent 引擎

- 状态：已采纳（2026-10-15）
- 相关：[04 引擎适配](../design/04-engines.md)

## 背景

SMA 需要"调模型、执行工具、在沙箱里跑命令"的能力。自己写这层循环工作量大，而 Codex CLI、Claude CLI 已经提供了成熟的循环、工具、沙箱和登录，并且都支持非交互运行、结构化输出和事件流。开发测试阶段本人主要用 Codex CLI；后期要支持本机 Codex 登录和自定义 API；模型要混用。

## 决定

每个步骤交给一个现成的引擎执行：开发期以 Codex CLI 为主，之后接入 Claude CLI 和 OpenAI 兼容的自定义 API。适配层统一接口，Agent 包只声明需求（模型家族、档位、沙箱、工具），不写死引擎。评审类角色默认和出方案的角色用不同的模型家族。

## 代价与影响

- 能用上本人现有的登录和额度，开发量小很多；但要跟着引擎的版本变化做适配。
- 引擎的读权限拦不住，隔离要靠工作目录、只给本账号路径和事后扫描。
- 一次运行有十几次引擎调用，额度消耗明显，需要记录用量。

## 考虑过的其他方案

- 用 OpenAI Agents SDK 或 LangGraph 从零写循环：控制力强，但 Codex 现成的工具、沙箱和登录都用不上，还要按 API 计费。保留为以后的一个引擎选项。
- 做成 Codex 或 Claude 的插件：最快，但没有自己的编排、状态和评测，达不到目标。
