## 1. M1 告诉我们什么

| 发现 | 对 M2 的影响 |
|---|---|
| 网页搜索基本拿不到抖音、小红书的作品数据，也看不了视频（`media_reviewed` 全是 false），找到的多是 B 站 | 研究工具（Chrome 只读）是第一优先：真实平台数据、作者主页算常态、评论、播放截图 |
| 调研每路 130–490 万输入 token：一轮几十次搜索，每次都重发上下文 | 研究工具直接返回结构化数据，常态和倍数由代码算，减少来回搜索 |
| 三路创意会撞题（"等泡面的三分钟"出现两次），候选要比较和取舍 | 盲评和返工是第二优先 |
| 模型会把账号文件当证据、写出没看过的链接；Schema 说明、校验和修复重试能兜住 | 新增产物都按同样的方式做：Schema 说明写清、语义规则、证据核对 |
| 只有 Codex 可用，型号全是同一家族 | 评审要做到"异家族"，得接 Claude；否则先用同家族的另一个型号，并在依据卡里注明 |

## 2. 范围（建议）

M2 只做"一句话 → 选定创意和制作方案"的完整闭环，中途不需要确认。

| 做 | 内容 |
|---|---|
| 研究工具 `sma-research` | 每个账号一份专用 Chrome 登录资料，用 Playwright 只读操作：搜索、作者作品、作品详情、评论、播放截图；每次取数记进证据台账 |
| 规划 | `planner` 包：判断任务类型，挑研究方向和 3 种创意方法；方向调整类任务不进创意流程 |
| 盲评与返工 | `creative-critic` 包：盲评打分、核对证据、查相似度、选方案；要改就定向返工，都不行就重出一轮，最多 2 轮 |
| 导演 | `film-director` 包：制作方案和镜头表（不生成素材，生成是 M3） |
| 依据卡 | 代码生成：选中的创意、市场证据、评审摘要、风险、用了哪些模型 |
| 编排 | 按规划结果动态展开、盲化、返工循环、过线检查 |

| 往后放 | 放到 | 原因 |
|---|---|---|
| strategy 流程（诊断 → 保留／放弃确认 → 对标 → 至少 3 个方向 → 写回定位）和 checkpoints 模式 | M2b | 多轮人机确认，单独做；M2 先做"方向调整不进创意、先复述"的拦截 |
| 增长分析的账号基线 | M4，和数据回流一起 | 新账号没有数据；有数据的账号，它的价值主要在回流 |
| `sma-workspace` 服务 | M3 | 输入用文件快照够用 |
| `sma-media`（抽帧、转写） | M3 | 主要给审片用；M2 看别人的作品用浏览器播放截图 |

## 3. 需要你决定的

1. **范围**：按上面拆成 M2（创意闭环）和 M2b（strategy 流程），还是一次做完？建议拆开，先做创意闭环。
2. **评审用哪家模型**：

3. **研究平台**：首批做小红书、抖音，B 站顺带（公开数据多，最好做）？研究要在 SMA 打开的 Chrome 里登录平台账号，建议用小号，因为自动浏览有风控风险。

## 4. 方案

### 4.1 研究工具 `sma-research`

- **浏览器**：`sma browser open` 用账号工作区的 `.sma/browser/` 启动 Chrome。窗口可见，本人自己登录；SMA 不输入密码、不扫码、不处理验证码。调试端口只监听本机，不碰你日常用的 Chrome。
- **工具**（全部只读）：

| 工具 | 返回 |
|---|---|
| `search(platform, query)` | 作品列表：链接、标题、作者、看得到的指标、发布时间 |
| `author_posts(author_url, n)` | 作者近 n 条作品和指标；常态中位数和每条的倍数由代码算好 |
| `post_detail(url)` | 指标原文和数值、发布时间、文案、话题 |
| `comments(url, n)` | 热门评论原文和点赞数 |
| `playback_frames(url, seconds)` | 播放作品，按时间点截图（前 3 秒截得密一些），存进步骤目录 |

- **取数方式**：从页面自己加载的数据里取（页面状态和页面请求的返回），不靠页面结构，平台改版时不容易坏。每个平台一个适配器。
- **证据台账**：每次调用存一条 `evidence/ev-N.json`（链接、时间、取到的字段、截图路径）。爆款条目必须写台账编号，校验时核对三件事：编号存在；指标和台账一致；`media_reviewed` 为真时，必须有这个作品的播放截图。这比 M1 的"链接出现过"更严。
- **风控保护**：同一平台的访问全局限速，多个研究步骤共用一份限速；单步打开的页面数有上限（这是风控限制，不是预算）。遇到登录页或验证码就停下，发阻塞报告，说明去窗口里处理。
- **研究步骤**改为只用这些工具（`network: tools-only`）。网页搜索要不要保留作补充，实测后定。
- **回放模式**：把实测时取到的数据录下来，评测时由一个假的研究服务回放，不碰真实平台，结果可重复。

### 4.2 规划 `planner`

- **输入**：任务原话、定位快照、最近 5 次运行的选题摘要（避免重复）、流程允许的研究方向和创意方法。
- **输出 `run-plan`**：任务类型（content／direction-change／question）、1–3 个研究方向（每个附上这次的重点）、恰好 3 种创意方法、说明。
- **代码校验**：取值不在允许范围或数量不对，就用流程定义里的默认值，并记进运行记录。
- **方向调整**：不启动研究和创意，交一份复述（保留／放弃／新增，以及要问清的核心资产问题），运行转为阻塞，新增阻塞原因 `direction-change`。这条来自 AI-SMA 停更账号测试的失败教训。

### 4.3 盲评与返工

- **盲化**（代码）：合并三路候选，去掉方法标签，候选代号打乱重编成 X1、X2……（用运行 id 做随机种子）。
- **打分**：沿用 AI-SMA 的 7 个维度（证据、钩子、清晰、回报、新颖、一致、可行，各 0–5 分）。过线条件：总分不低于 25，每项不低于 3，"一致"不低于 4，选中的方案没有相似度问题。阈值写在包里，由代码校验。
- **结论**：
  - pass：交给导演。
  - revise：只返工选中的那一个，交回产出它的那一路创意总监，带着 `required_changes`，改完再评一次。
  - reject：带着评审意见重出一轮 3 路。
  - 返工和重出合计最多 2 轮（`autonomy.idea_rounds_max`），用完就阻塞（`rounds-exhausted`）。
- **探索名额**：评审可以另选一个也过线、但更新颖的 `explore_pick`。按 `autonomy.explore_ratio`（默认 0.2）的比例由代码决定这次做哪个，依据卡里写明。
- **独立性**：评审和创意总监用不同的模型家族（见第 3 节第 2 条）。

### 4.4 导演 `film-director`

- **输入**：选中的候选（返工后的版本）、评审要求、定位和内容规则、`sma.yaml` 里的交付规格和启用的制作路线。
- **输出**：
  - `production-plan`：第 1 秒、第 3 秒、转折、回报，以及风格、资产、声音、风险；
  - `shot-list`：逐镜头的时长、画面、动作、机位、声音、字幕、素材，要不要生成，生成的提示词。
- **规则**：镜头时长加起来等于总时长；镜头 id 不重复；引用的固定资产在 `固定资产/` 里真的存在。
- **技能**（都可选）：direct-video、ai-video-prompt、huashu-art-motion。

### 4.5 依据卡

运行结束时由代码写 `runs/<运行>/依据卡.md` 和 `delivery-rationale` 产物，内容包括：

- 选中的创意和理由；
- 市场证据（爆款条目、链接、倍数、台账编号）；
- 评审分数、风险和相似度检查；
- 用了哪些包和模型（同家族评审会注明）；
- 用量。

`sma run` 结束时直接打印选中方案的一句话和依据卡路径。

### 4.6 编排层

| 能力 | 用在哪 |
|---|---|
| 按上游产物动态展开 `foreach`（规划结果），校验不过就用默认值 | research、ideation |
| 输入变换：盲化 | review |
| 返工循环：按评审结论回到上游，带上意见，有轮数上限 | review → 返工或重出 |
| 过线检查（`gate`） | review → direct |
| 新的阻塞原因 `direction-change` | plan |
| 步骤挂载 MCP 服务，传入步骤目录和浏览器地址 | research |
| 续跑时清理上次没结束的引擎进程（SMA 被强制结束的情况） | 全部步骤 |

### 4.7 引擎

- 研究步骤挂载 `sma-research`。M1 的适配层已经支持按次挂载 MCP，实测过。
- 选 A 或 B 时加 Claude CLI 适配，评审默认走 Claude；没有登录时退回 C，依据卡里注明。

### 4.8 评测

| 包或场景 | 用例 |
|---|---|
| planner | 普通任务；方向调整（AI-SMA 停更账号测试第 4 句）；含糊的任务；研究方向和方法取值合法 |
| creative-critic | 正常选择；照搬标志性设定的候选必须被标出、不能被选；诱导它改写候选（不能改写）；引用不实要扣分 |
| film-director | 时长对得上；保留创意机制和评审要求；资产存在 |
| market-intel | 研究工具回放模式下的诚实性：没看过不写看过、指标和台账一致 |
| 场景「一句话创意」 | 测试工作区（虚构账号）端到端：中途 0 次确认；至少 9 个候选；盲评；选中方案能追到台账证据；产物全部过校验 |

接了 Claude 以后，包级评测再加上按评分标准打分（用另一家族的模型打）。

## 5. 对设计的调整

| 调整 | 原因 |
|---|---|
| 评审结论 revise 改为只返工选中的候选，reject 才重出一轮 | 设计里两种结论都退回 3 路重出，浪费，也不符合"改一改再做"的本意 |
| strategy 流程和 checkpoints 模式拆到 M2b，停更账号重启场景的验收跟着挪到 M2b | 范围太大；M2 先做方向调整的拦截 |
| 账号基线挪到 M4；`sma-workspace` 和 `sma-media` 挪到 M3 | 见第 2 节 |
| 研究工具 `profile_posts` 改名 `author_posts`，`open`、`screenshot` 先不做 | 按实际用途收窄；实测后再补 |
| 爆款条目加台账编号，Schema 升版本 | 证据核对从"链接出现过"升级到"数据和台账一致" |

## 7. 验收

1. **一句话任务**：在虚构账号上执行 `sma run "今天做一条视频"`，研究走真实平台。要求：
   - 中途 0 次确认；
   - 爆款条目来自平台真实数据，倍数由代码按作者常态算出，至少一部分作品真的看过画面；
   - 3 路至少 9 个候选，盲评选出方案，导演交出镜头表；
   - 依据卡能追到台账证据，全部产物通过校验。
2. **方向调整类任务**（例如"这个号以后不做猫了，改做职场"）：不进创意流程，交出保留／放弃／新增的复述和问题，运行阻塞。
3. 新包的评测全部通过；场景「一句话创意」通过。
4. 汇报每次运行的耗时、引擎调用次数和用量，和 M1 对比。

## 8. 风险

| 风险 | 应对 |
|---|---|
| 平台风控：自动浏览可能触发验证，或限制账号 | 低频、限速、只读、用小号；遇到验证就停下请你处理，不尝试绕过 |
| 平台改版导致取数失败 | 从页面数据取，不靠页面结构；每个平台一个适配器；取不到就写进缺口，不让整次运行失败 |
| 浏览器调试端口被本机其他程序利用 | 只监听本机；用专用资料目录，和日常 Chrome 分开 |
| Claude CLI 的隔离做不干净 | 0b 实测不通过就退回方案 C，不带着隐患上线 |
| 用量：一次完整运行估计 200–500 万输入 token（大部分命中缓存），20–40 分钟 | 每步用量都可查；研究工具返回结构化数据，预计比 M1 的纯网页搜索少 |
