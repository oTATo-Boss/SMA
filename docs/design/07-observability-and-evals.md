# 07 追踪与评测

- 状态：草案 v0.1
- 相关：[03 流程与编排](03-workflow.md)、[04 引擎适配](04-engines.md)、[06 工作区与数据](06-workspace-and-data.md)

## 1. 追踪

每次运行留下三层记录：

| 层 | 内容 | 存在哪里 |
|---|---|---|
| 运行 | 流程、任务原话、模式、状态、总耗时、总用量、阻塞原因 | 状态库 `runs` |
| 步骤与尝试 | 包和版本、引擎、型号、输入产物的哈希、输出、校验结果、重试原因、耗时、用量 | 状态库 `steps`、`attempts` |
| 引擎事件 | 引擎原样输出的事件流：模型回复、工具调用、命令执行 | 尝试目录的 `events.jsonl` |

- 查看：`sma runs show <运行>` 按步骤列出状态、耗时和产物；`--step <步骤>` 看某一步的输入、输出和事件摘要。
- 写盘前按值脱敏密钥（[05](05-tools-and-policy.md) 第 4 节）。
- 以后需要接外部观测平台时，按 OpenTelemetry 的 GenAI 约定导出；现阶段不引入。

## 2. 评测的层级

| 层 | 测什么 | 怎么测 | 什么时候跑 |
|---|---|---|---|
| L1 合同 | 产物格式和语义规则 | 四层校验（[02](02-contracts.md) 第 4 节），每一步自动执行 | 每次运行 |
| L2 包 | 单个 Agent 包的能力 | 包的 `evals/cases.jsonl`：确定性检查加异家族模型按评分标准打分 | 改包、换模型、换引擎之前和之后 |
| L3 流程 | 端到端场景 | `evals/` 里的场景：输入是一句话和一个测试工作区，检查结果和过程指标 | 改流程或多个包之后 |
| L4 本人评分 | 是否达到本人的要求 | 本人给成品和中间产物打分，记入状态库，用来校准评审包 | 日常使用 |
| L5 市场 | 真实效果 | 发布数据和账号常态比较，形成经验更新 | 有数据时 |

## 3. 包级评测

```text
sma eval agent creative-critic                  跑这个包的全部用例
sma eval agent creative-critic --model <型号>   换型号对比
sma eval compare <评测 A> <评测 B>              两次结果逐条对比
```

- 用例的输入产物放在包的 `evals/fixtures/`，不依赖真实账号数据。
- 打分用的模型和被测包不同家族；打分标准写在包的 `evals/rubric.md`。
- 结果写进状态库 `evals` 表；包升版本时，`CHANGELOG.md` 附上和上一版的对比。

## 4. 流程级场景

首批场景，迁自 AI-SMA 的测试用例：

| 场景 | 输入 | 通过标准（摘要） | 里程碑 |
|---|---|---|---|
| 一句话创意 | 定位已确认的测试工作区；"今天做一条视频" | 中途确认 0 次；3 路至少 9 个候选；盲评；选中方案能追到爆款证据；产物全部过校验 | M2 |
| 停更账号重启 | 原样重放一段测试对话 | 方向调整先复述"保留／放弃／新增"、问清核心资产；定位没确认不出具体选题；不读取、不引用全局记忆 | M2 |
| 一句话视频 | 同上，跑完整流程 | 完整内容包；审片来自实际抽帧和声音；可修的问题自动返工；付费任务无重复提交 | M3 |

场景的测试工作区放在仓库的 `evals/workspaces/`，内容是虚构的测试账号，不放任何真实账号的数据。

## 5. 回归流程

1. 改 Agent 包、提示词、模型或流程之前，先跑一遍相关的 L2 和 L3，作为基线。
2. 改完再跑一遍，用 `sma eval compare` 对比。
3. 变差的用例要么修好，要么在变更记录里写明为什么接受。
4. 出过的错都补成用例，例如"把一句话理解错并直接写进定位"。

## 6. 核心指标

| 指标 | 含义 | 目标 |
|---|---|---|
| 中途确认次数 | full 模式下一次运行里需要本人确认的次数 | 0 |
| 校验通过率 | 产物第一次就通过四层校验的比例 | 持续上升 |
| 评审一致率 | 创意评审的选择和本人选择一致的比例 | 用来校准评审包 |
| 免改可用率 | 成品不用修改就能发的比例 | 工程目标：连续 10 条里至少 8 条 |
| 返工轮数 | 每次运行的返工次数 | 持续下降 |
| 运行耗时与用量 | 每次运行的总耗时、引擎调用次数和用量 | 可查、可比较 |
| 市场表现 | 发布后相对账号常态的表现 | 不用模型自评代替 |

免改可用率只说明是否达到本人的要求；能不能涨粉，要靠持续发布、积累可比较的样本判断。
