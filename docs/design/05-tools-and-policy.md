# 05 工具与策略

- 状态：草案 v0.1
- 相关：[04 引擎适配](04-engines.md)、[06 工作区与数据](06-workspace-and-data.md)、[ADR-0004](../adr/0004-tools-via-mcp-policy-as-capability.md)

## 1. SMA 的 MCP 服务

Agent 能用的外部能力，全部通过 SMA 自己写的 MCP 服务提供。每个步骤只挂载包里声明的服务和工具。

| 服务 | 工具 | 读写 | 主要使用者 | 里程碑 |
|---|---|---|---|---|
| `sma-research` | `search`（平台、关键词）、`open`、`profile_posts`、`post_detail`、`comments`、`screenshot`、`playback_frames`（播放时按时间点截图） | 只读 | 市场研究、增长分析 | M2 |
| `sma-media` | `probe`、`frames`、`contact_sheet`、`loudness`、`scene_cuts`、`transcribe`（可选依赖） | 只写尝试目录 | 市场研究、审片、后期 | M2 |
| `sma-generate` | `providers`、`submit`（带幂等键）、`status`、`fetch` | 有副作用，受台账约束 | 素材制作 | M3 |
| `sma-workspace` | `strategy`、`library_search`、`benchmarks`、`assets_list`、`memory` | 只读 | 所有包 | M2（M1 的输入以文件快照放进步骤目录） |

- **没有任何写平台的工具。** 发布、评论、私信、点赞、关注，SMA 里根本不存在对应的能力。
- **入库和打包不是工具，是代码。** 爆款条目入库、经验写入、内容包复制到 `交付/`，都由编排层在校验后执行。
- **生成服务可插拔。** 第一个提供方是 RunningHub；图片、配音等以后按同一接口接入。每个提供方要在账号配置里有本人的授权记录，没有就发一次阻塞报告（`needs-authorization`），授权写入后不再问。

## 2. 红线落在哪里

| 红线 | 怎么执行 | 在哪一层 | 剩余风险 |
|---|---|---|---|
| 不发布、不互动 | 没有任何写平台的工具；研究工具只提供读操作；引擎不加载用户的插件和扩展 | 工具、引擎 | 低 |
| 只写自己的目录 | 沙箱只允许写当前尝试目录；Agent 只交产物，入库和打包由代码完成 | 沙箱、编排 | 读权限拦不住（见第 5 节） |
| 交付只增不改 | 只有打包步骤能写 `交付/`；目标目录已存在就失败 | 编排 | — |
| 付费任务不重复提交 | `sma-generate` 的台账按幂等键去重；续跑先查询原任务 | 工具 | 提供方自身的重复扣费，靠记录任务 ID 追查 |
| 密钥不外泄 | Key 只在环境变量或系统钥匙串；不进指令、任务、产物；追踪记录按值脱敏 | 编排、追踪 | 引擎自身日志，写入前扫描 |
| 自主与确认 | full 模式中途不确认；定位确认是唯一关口；checkpoints 模式按声明暂停 | 编排 | — |
| 方向先复述 | 涉及方向调整的任务不进创意流程，改走 `strategy` 流程先复述、等确认 | 编排、规划 | 规划 Agent 漏判，靠回归评测兜底 |
| 不串号、不用全局记忆 | 不读用户配置；只给本账号路径；产物里出现其他账号名称就报错；经验只存在本账号工作区 | 引擎、校验 | 读权限拦不住（见第 5 节） |
| 抄结构不抄表达 | 评审必查相似度（`similarity_flags`）；研究得到的截图、抽帧、转写不进交付 | 评审、打包 | 判断依赖模型，靠评测集校准 |

## 3. 策略摘要

编排层给每一步生成一段统一的策略摘要，写进 `AGENTS.md` 的开头，内容只有：

- 本步骤能写哪里（当前目录，或什么都不能写）；
- 不能发布、不能和任何人互动；
- 只能读哪些路径（本账号工作区里给出的文件）；
- 不要采用对话外的任何记忆或其他项目的信息；
- 交什么产物、格式由 Schema 约束。

摘要对所有包一致，由代码生成，不在各包的指令里重复。

## 4. 密钥

| 环节 | 做法 |
|---|---|
| 保存 | 系统钥匙串（`sma secrets set <名字>`，隐藏输入）或环境变量；不放进账号工作区 |
| 使用 | 引擎和工具只拿到环境变量名，值在进程环境里 |
| 记录 | 追踪层写盘前，把已知密钥的值替换掉；引擎事件流同样处理 |
| 检查 | `sma doctor` 扫描工作区文件，发现疑似密钥就报出来（沿用 AI-SMA 的密钥检查） |

## 5. 隔离

- **引擎层**：不读用户配置，所以全局记忆、个人插件、个人 MCP 都不进来；会话不落盘；工作目录是尝试目录。
- **数据层**：一次运行只绑定一个账号工作区；工具只接受这个工作区；爆款库和经验按工作区分开存。
- **检测**：SMA 知道本机登记过的所有账号工作区，每一步的产物都扫描有没有其他账号的名称和路径，比 AI-SMA 按同级文件夹名猜更准。本账号自己的名字和 `isolation.allowed_terms` 覆盖住的位置不算；命中时带着 JSON 位置修复重试，提示里只露出名称的首尾字，不把其他账号的名称写进本账号的记录。运行前后还给工作区拍快照，SMA 目录以外的文件有变化就记一条检查。
- **诚实的限制**：引擎进程能读到磁盘上的其他文件，沙箱主要限制的是写。现阶段靠只给本账号路径和事后扫描兜底；以后可以让引擎在单独的系统用户或容器里运行。

## 6. 浏览器研究

- 每个账号一个专用的 Chrome 用户目录，放在工作区的 `.sma/browser/` 里；里面有登录信息，不进备份和版本库。
- SMA 启动这个 Chrome（有窗口，方便本人登录），只监听本机端口，`sma-research` 通过 Playwright 连接。
- 遇到登录页就返回"需要登录"，编排层发阻塞报告；本人自己登录，SMA 不输入密码、不扫码。
- 低频访问，有限速；平台规则和风控风险记在 [00](00-overview.md) 第 13 节 R4。
- 后续如果要用付费数据接口（例如外部研究技能用的 ScrapeCreators），也作为 `sma-research` 的另一个数据源接入，不改 Agent 包。

## 7. 外部内容与版权

- 研究得到的截图、抽帧、转写只存在运行目录里，用于分析，不进交付。
- 素材清单记录每个素材的来源和许可；打包时只收自己生成、固定资产和许可明确的素材。
- 引用外部技能里的案例和方法原文时，按其许可注明出处（例如 CC BY 4.0）。
